# Передача исходников покупателю

Решение продавца от 12 октября 2026: **продаётся код; покупатель сам организует установку**. Эта поставка — приложение онлайн-записи с PostgreSQL, защищённой админкой и внутренними TEST-платежами. Настоящее списание денег, уведомления и установка на сервер не включены. Результаты проверки: [SALE-AUDIT.md](qa/SALE-AUDIT.md).

## Кто что делает

| Задача | Ответственный при продаже только кода |
| --- | --- |
| Исходники, lock-файл, миграции, инструкции и описание ограничений | Продавец |
| Условия использования кода, объём поддержки и критерии приёмки | Продавец и покупатель согласуют до сделки |
| Домен, хостинг с Node.js, PostgreSQL и оплата этих услуг | Покупатель, на своих аккаунтах |
| Установка, DNS, HTTPS, защита сервера, мониторинг и резервные копии | Покупатель или его разработчик |
| Данные салона, реальные услуги, цены, мастера, графики, фото и документы | Покупатель предоставляет; его установщик настраивает |
| Новый аккаунт владельца и пароли/секреты | Покупатель |
| Реальный платёжный провайдер и уведомления, если нужны | Отдельная разработка по требованиям покупателя |

Продавцу для передачи кода не нужно оплачивать домен или хостинг. Локальной демонстрации достаточно для показа функций. Установка или поддержка становятся обязанностью продавца только если отдельно включены в сделку.

## Где что хранится

Это одно приложение: клиент открывает `/`, администратор — `/admin/login`. Оба интерфейса работают с одним сервером и одной PostgreSQL. Не нужны два отдельных сайта или два домена.

Исходники находятся в архиве/репозитории. База PostgreSQL хранит услуги, настройки, графики, клиентов, записи и платежные события. После установки данные сохраняются в базе покупателя, а не в GitHub. Файлы фото находятся в `public` или доступны по заданным HTTPS URL; встроенного загрузчика фото нет. Домен — адрес сайта; хостинг запускает приложение.

GitHub Pages обслуживает статические файлы и не заменяет сервер этого приложения с API и PostgreSQL: [официальное описание](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Подходящий сервер должен поддерживать постоянный Node-процесс и доступ к PostgreSQL; [официальная инструкция Next.js](https://nextjs.org/docs/app/guides/self-hosting).

## Что передать

1. Архив актуальных исходников: `src`, `public`, `prisma` с миграциями, `scripts`, `tests`, `deploy`, документацию, настройки сборки, `package.json`, `package-lock.json`, `.env.example`.
2. Эту инструкцию, [README](../README.md), [DEPLOYMENT](DEPLOYMENT.md), отчёт проверок и список ограничений.
3. Отдельно согласованные условия: покупатель может ли изменять/перепродавать код, сколько установок разрешено, входит ли поддержка и на какой срок. В проекте не добавлена общая лицензия; технический архив не заменяет условия сделки.

**Не передавать** свою `.env`, пароли, `.local`, дампы локальной базы, реальные клиентские данные, `node_modules`, `.next` и Git-историю. Покупатель создаёт собственные секреты и пустую базу. Миграции передаются вместо базы продавца; демонстрационное заполнение — отдельная команда.

Создание архива на Windows из текущего проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-source.ps1
```

Архив и SHA256 появляются в игнорируемом `artifacts`. Скрипт включает текущие изменения и новые файлы, перечисленные Git, и отклоняет известные пути конфигурации с секретами/данных. Он не является универсальным сканером секретов: перед передачей проверьте свои новые файлы. Git-история в архив не входит.

Если продаёте доступ к закрытым исходникам, учитывайте публичность существующего репозитория. GitHub допускает просмотр и fork публичного кода; ранее сделанные копии остаются и после закрытия: [документация GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository). Смена видимости не выполнялась. Права на сторонние библиотеки, шрифты и фото учитываются отдельно; не обещайте исключительность ранее опубликованного кода без проверки условий.

## Проверка покупателем на своём компьютере

1. Распаковать исходники в отдельную папку. Установить Node.js >=22.12 (проверен Node 24.20), npm и PostgreSQL (проверена версия 17.11).
2. Выполнить `npm ci`. Скопировать `.env.example` в свою `.env` и настроить свою PostgreSQL. Для Windows доступна инструкция portable-базы в [DEPLOYMENT](DEPLOYMENT.md); для Docker — [README](../README.md).
3. Только в отдельной demo-базе: `npm run db:migrate`, затем `npm run db:seed`. Для сценария TEST включить адаптер и собственный случайный секрет по README. Не использовать реальные контакты для demo.
4. Выполнить `npm run build`, затем `npm start`. Открыть `http://127.0.0.1:3000`.
5. В интерактивном терминале создать нового владельца: `npm run admin:create -- --email owner@example.com --name "Владелец"`. Заменить email/имя своими, скрыто ввести пароль. Повтор команды не меняет пароль существующего аккаунта.
6. Открыть `/admin/login`, проверить настройки и запись. Повторить проверки из DEPLOYMENT; интеграционные тесты запускать только на demo-подключении.

## Что ещё требуется для настоящего салона

Для продажи исходников инфраструктура не нужна. Для объявления «полностью установленный рабочий сайт для салона» необходима дополнительная подготовка:

- **Начальное заполнение чистой реальной базы.** `db:seed` создаёт demo и запрещён в production. Отдельной команды создания настоящего `SalonSettings` сейчас нет; форма настроек не создаёт отсутствующую строку. Установщик должен добавить согласованный bootstrap/импорт настоящих сведений и документов, затем каталог, назначения и графики. Нельзя просто запустить demo-seed на рабочей базе или изменить одну переменную.
- **Публичные тексты.** Проверить демонстрационные подписи, фото, description и запрет индексации в `src/app/layout.tsx`. Менять их под настоящий салон; включать индексацию только после проверки документов и готовности сервиса.
- **Учётные записи.** CLI создаёт первого владельца, но самостоятельного восстановления/изменения забытого пароля в интерфейсе нет. Если это обещается покупателю, потребуется отдельная функция или согласованная процедура администратора системы.
- **Оплата и уведомления.** Внутренний TEST не является банковским sandbox. Реальный провайдер, возвраты, SMS/email не реализованы. До их подключения production должен работать с `PAYMENT_MODE=DISABLED` и без требования онлайн-предоплаты.
- **Сервер.** Покупатель размещает код, применяет миграции, настраивает постоянный Node, PostgreSQL, HTTPS-прокси, закрывает прямой доступ к базе/Node, запускает `deployment:check` с `APP_ENV=production`, проверяет backup и восстановление. Шаблоны nginx/systemd ещё не проверены на удалённом сервере.
- **Приёмка после установки.** Проверить реальный HTTPS-вход/выход, запись и занятость времени, календарь/перенос/отмену, перезапуск и сохранение данных, доступ без сессии, резервную копию и восстановление. Повторить проверку зависимостей на дату установки.

Название/цены/графики предоставляет покупатель. Универсальный bootstrap настоящей установки, если продавец обещает готовую установку без разработки, относится к подготовке самого продукта. Его отсутствие явно отражено в поставке. Для текущей сделки честное описание: **«Исходники системы онлайн-записи с админкой и тестовой оплатой; самостоятельная установка, реальные платежи и уведомления отдельно»**.
