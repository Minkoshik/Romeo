# РОМЕО — онлайн-запись в салон

Русскоязычный сайт для одного салона и нескольких мастеров. Реализованы каталог и расписание PostgreSQL, сохранение клиентов и записей, временные брони, тестовая предоплата и просмотр по личной ссылке. Путь клиента: услуги → мастер → дата → время → контакты → проверка → бронь → тестовая оплата → подтверждение. Без требуемой предоплаты запись подтверждается сразу. Результаты этапов и проверок записаны в [PROGRESS.md](PROGRESS.md). Дальнейшие этапы выполняются только после команды «Продолжи этап N».

Демонстрационный салон: **РОМЕО**, Москва, Большая Никитская, 22. Валюта — рубль (`RUB`), часовой пояс — `Europe/Moscow`. На этапе 3 публичные настройки после загрузки каталога берутся из `SalonSettings`. Переменные `SALON_NAME`, `SALON_ADDRESS`, `SALON_PHONE`, `SALON_CURRENCY`, `SALON_TIMEZONE` и `SALON_COUNTRY` нужны для начального заполнения и предварительной оболочки. Это демонстрационные сведения.

После изменения `.env` перезапустите сервер. Изменение окружения само по себе не обновляет сохранённые настройки `SalonSettings`: для локальных демонстрационных данных их переносит `db:seed`. Настройки из базы проверяются сервером и передаются в интерфейс; редактирование через админку появится на этапе 7.

## Что работает сейчас

- Общее оформление: светлый фон, белые карточки, центральная колонка, шапка, навигация и панель выбранных услуг.
- Каталог из PostgreSQL с поиском, категориями, выбором нескольких услуг и пересчётом стоимости и длительности; начальное заполнение демонстрационное.
- Выбор мастера, выполняющего весь набор услуг, и пересчёт итогов с его индивидуальными ценами и длительностями.
- Календарь и время по графикам PostgreSQL: исключения на дату, обед, блокировки, занятые интервалы и ближайшее свободное начало для всей процедуры с техническим перерывом.
- Контактная форма с проверкой имени, телефона, необязательного email и согласия с демонстрационными условиями.
- Проверка записи с редактированием каждого шага и серверным пересчётом стоимости.
- Сохранение нормализованных клиентов, записей и снимков услуг/условий в PostgreSQL; защита от пересечений транзакцией и SQL-ограничением, от повторов — ключом идемпотентности.
- Настоящая временная бронь с серверным сроком и автоматическим истечением независимо от браузера; без требуемой предоплаты запись подтверждается сразу.
- Личная страница записи с серверным статусом и сохранёнными условиями, доступная после перезагрузки по секретной ссылке.
- Тестовый платёжный адаптер для броней в базе: успех, ошибка, отмена и истечение сессии; повторная попытка сохраняет исходный срок брони.
- Проверка подписи серверных событий, суммы, валюты и принадлежности платежа; атомарное подтверждение и защита от повторных событий.
- Поздний успешный платёж повторно проверяет исходный интервал. При конфликте платёж сохраняется для проверки салоном, запись не занимает чужое время, возврат не имитируется.
- Внесённая сумма, остаток, история тестовых попыток и файл `.ics` для подтверждённого визита.
- Страница информации о салоне и безопасная заготовка административного раздела.
- Prisma с PostgreSQL-адаптером, применённые миграции, повторяемое демонстрационное заполнение и серверная проверка конкретных вариантов услуг и назначений мастера.

Женская стрижка показывается как одна услуга за **2 800 ₽ / 1 час**, без выбора длины волос. Остальные услуги с несколькими вариантами сохраняют переключатель.

**Доступность, записи, брони и тестовые платежи работают с PostgreSQL; начальное заполнение салона, каталога и графиков демонстрационное.** Проверенный успех тестового адаптера подтверждает запись в базе. Денежного списания нет; настоящий провайдер и уведомления не подключены. Для проверки используйте вымышленные контакты.

## Быстрый запуск в PowerShell

Рекомендуется **Node.js 24 LTS**; минимальная версия — **22.12**. Для загрузки каталога нужна подготовленная PostgreSQL. На Windows доступны portable-скрипт проекта и Docker; выберите один вариант запуска базы.

В папке проекта выполните:

```powershell
npm ci
if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
```

Если `.env` уже существует, сохраните его и добавьте недостающие параметры вручную. Демонстрационные значения в `.env.example` предназначены для локальной разработки, а не для размещения публичного сервиса.

После установки автоматически выполняется `prisma generate`. Он создаёт игнорируемый Git клиент Prisma и не требует `DATABASE_URL` или запущенной базы. Это позволяет собирать проект после свежей установки зависимостей.

Подготовьте PostgreSQL по разделу ниже и проверьте настройки подключения, затем примените миграции и заполнение:

```powershell
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

`db:seed` предназначен для локальной демонстрационной базы. Он не требуется для базы с собственным подготовленным каталогом.

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Сервер привязан к локальному адресу `127.0.0.1`. Завершить его можно сочетанием `Ctrl+C`.

Для проверки производственной сборки:

```powershell
npm run build
npm start
```

## Тестовая оплата

Пользователь выбрал только тестовый режим. В локальном `.env` он уже настроен; секрет не публикуется. Для новой установки `.env.example` по умолчанию отключает платежи. Чтобы включить внутренний адаптер, задайте:

```dotenv
APP_ENV=demo
PAYMENT_MODE=TEST
PAYMENT_WEBHOOK_SECRET=<случайный секрет не короче 32 байтов>
```

Создать случайный секрет можно локально командой `node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"`. Сохраните результат только в `.env` и перезапустите сервер. Настройки `SalonSettings.isDemo` должны оставаться `true`. `APP_ENV=production`, другое значение режима, слабый/отсутствующий секрет или настоящий салон отключают тестовую оплату. Производственная сборка Next.js с `NODE_ENV=production` может запускаться локально с явным `APP_ENV=demo`.

Создайте бронь и на личной странице нажмите «Перейти к тестовой оплате», выберите исход и выполните сценарий. Результат проходит через тот же проверяемый серверный обработчик, что и подписанное уведомление; браузерный переход или флаг успеха не подтверждают запись. Ошибка, отмена и истечение платёжной сессии допускают новую попытку, пока исходная бронь действует. Истечение всей брони освобождает время независимо от браузера.

Тестовые суммы явно помечены в интерфейсе и календаре. При поздней оплате сервер повторно проверяет расписание и занятость: свободный исходный интервал подтверждается, конфликт сохраняется с `needsAttention`. Дополнительный успешный платёж тоже требует проверки салоном. Админка и настоящие возвраты — последующие этапы. Интеграция внешнего провайдера отложена до выбора страны, валюты и провайдера; его официальный sandbox не подключён.

`GET /api/catalog` возвращает активные категории, услуги, варианты и доступных для записи мастеров из PostgreSQL. Источник обозначается `source: "database"`, демонстрационные строки сохраняют отметку `isDemo`. Параметры `search` и `category` проверяются Zod на сервере; категория принимается по UUID или slug, некорректный запрос получает ответ `400` с сообщением на русском языке.

`POST /api/catalog/selection` получает `variantIds` и `masterId`, проверяет активность вариантов и назначение каждого выбранному мастеру. Клиентская совместимость помогает выбрать мастера, а окончательная проверка выполняется сервером. При недоступной или пустой базе каталог не подменяется встроенными демонстрационными данными; интерфейс показывает соответствующее состояние и повторную попытку.

Черновик услуг, мастера, даты, времени и контактов хранится только в памяти React Context: сохраняется при переходах внутри сайта и возврате, очищается при перезагрузке страницы. `sessionStorage` и `localStorage` не используются. Проверка quote не сохраняет контакты; создание записи сохраняет клиента и контактный снимок в PostgreSQL. После создания запись открывается по личной ссылке независимо от черновика. Используйте вымышленные данные для локальных проверок.

При изменении услуг совместимый мастер сохраняется, несовместимый сбрасывается. Дата и время сбрасываются при изменении услуг или мастера; смена даты сбрасывает время. Изменение данных отменяет прежний расчёт черновика. Уже сохранённая запись от изменения выбора не отменяется.

`POST /api/demo/quote` заново проверяет сочетание вариантов и мастера, цены, длительности, перерывы и выбранное время по одной транзакционной выборке PostgreSQL. Дата, время, контакты и согласие проверяются сервером; суммы и длительности клиента не используются. Если выбранный интервал уже недоступен, возвращается `409`. Страница проверки заново обращается к серверу при каждом возврате на неё. Ответы не кешируются, контакты запроса не записываются этим обработчиком в базу. Сохранение выполняется отдельным `POST /api/appointments`, который повторяет проверки внутри транзакции.

## Серверное расписание этапа 4

`GET /api/availability?masterId=<UUID>&variantId=<UUID>&date=YYYY-MM-DD` принимает один идентификатор мастера и повторяющийся `variantId` для 1–20 услуг. Дата необязательна; без неё возвращаются календарь и интервалы сегодняшнего дня. Дата должна входить в горизонт записи салона. Посторонние параметры, включая клиентскую стоимость или длительность, отклоняются с `400`.

Недельные рабочие интервалы читаются из `WeeklySchedule`. Исключения имеют приоритет: `CLOSED_DAY` закрывает дату; `REPLACE_DAY` заменяет недельный график своими рабочими интервалами; `BLOCKS_ONLY` вычитает блокировки из обычного графика. Блокировки также вычитаются из замены. Отсутствующий график означает отсутствие свободного времени. Обед возникает из разрыва рабочих интервалов, а не из фиксированных часов в коде.

Сервер суммирует длительности выбранных услуг с индивидуальными значениями мастера. Технический перерыв после всего визита равен сумме эффективных перерывов выбранных вариантов и `SalonSettings.bufferMinutes`; индивидуальное значение `0` сохраняется. Весь визит вместе с этим перерывом должен поместиться в один непрерывный рабочий интервал и не пересечь занятую часть `[startsAt, occupiedUntil)`. Пример: две стрижки у Марка — 135 минут плюс 15 минут перерыва; начало 11:30 допустимо перед обедом в 14:00, начало 12:00 — нет.

Учитываются `CONFIRMED` и `WAITING_PAYMENT` с будущим `holdExpiresAt`; отменённые, завершённые и истёкшие интервалы не мешают расчёту. Чтение доступности не изменяет статусы. Сервер этапа 5 переводит просроченные брони в `EXPIRED` в фоне, перед созданием новой записи у этого мастера и при приватном просмотре записи. История сохраняется.

Горизонт, минимальное время до записи и шаг начала берутся из настроек базы. Сетка начинается от начала каждого рабочего интервала; блокировка не сдвигает её. Даты и часы рассчитываются в часовом поясе салона, моменты передаются в UTC. Несуществующее или неоднозначное время при переходе на летнее/зимнее время не предлагается. Публичный ответ содержит только календарь, интервалы, причины недоступности и итоговые условия; контакты, комментарии, идентификаторы записей и приватные причины исключений не читаются и не передаются.

Календарь и время обновляются каждые 30 секунд. Изменившиеся условия требуют обновить каталог; устаревший выбранный интервал блокирует продолжение. При ошибке базы возвращается `503`, интерфейс предлагает повтор. Встроенные фиктивные интервалы не используются как запасной источник. Редактирование расписания через защищённую админку относится к этапу 7.3.

Прежний `DEMO_SIMULATION` остаётся только в исторических автоматических тестах. Клиентский путь не использует его для подтверждения настоящих записей. Платёжный адаптер для реальных броней и подтверждение по проверенным событиям будут реализованы на этапе 6; календарный экспорт также должен опираться на настоящий статус записи.

## Записи и временные брони этапа 5

`POST /api/appointments` повторяет проверку контактов, согласия, выбранного мастера, услуг и всей доступности внутри транзакции PostgreSQL. Стоимость, длительность, перерыв и предоплата рассчитываются сервером. Интерфейс передаёт ожидаемые условия и SHA-256 версий текстов, чтобы изменение цены или условий после проверки требовало нового согласования, а не создавало неожиданную запись.

Создание работает с уровнем изоляции `Serializable`: сначала берётся транзакционная advisory-блокировка ключа повторного запроса, затем мастера. Сериализационные и уникальные конфликты повторяются с новой транзакцией. Дополнительно SQL-ограничение запрещает пересечение `[startsAt, occupiedUntil)` активных записей одного мастера; этот интервал включает технический перерыв. Конфликт откатывает и запись, и клиента, и позиции услуг. Будущие административные изменения графика и записей должны использовать ту же блокировку мастера.

Клиент создаёт один UUID `idempotencyKey` и секрет из 32 случайных байтов. После потерянного ответа повторяется тот же сохранённый запрос с прежним ключом и секретом. Сервер проверяет хеш секрета и отпечаток нормализованного запроса: одинаковый повтор возвращает прежнюю запись, изменённый запрос с тем же ключом получает `409`. Незавершённый запрос хранится в памяти вкладки; перезагрузка до получения личной ссылки очищает его. После успешного создания сохраните личную ссылку.

Если рассчитанная предоплата больше нуля, запись получает `WAITING_PAYMENT` и `holdExpiresAt` по часам PostgreSQL. Временная бронь закрывает интервал другим клиентам. Нулевая предоплата, включая нулевую настройку `FIXED` или `PERCENTAGE`, сразу даёт `CONFIRMED` без платежа. Платёжный адаптер ещё отсутствует: внесённая сумма равна нулю, симуляция оплаты не запускается и не подтверждает бронь.

В долгоживущем Node-сервере `npm run dev` или `npm start` обработчик истечения запускается автоматически: немедленно при старте и затем каждые 30 секунд. Он не требует открытого браузера, не запускает перекрывающиеся проверки и повторяет их после восстановления базы. Сборка не запускает обработчик. Перезапуск сервера обрабатывает накопившиеся просроченные брони; создание новой записи также освобождает просроченные брони этого мастера под его блокировкой.

Для размещения с отдельным постоянным процессом запустите в другом терминале или менеджере процессов:

```powershell
npm run holds:worker
```

Он использует тот же `DATABASE_URL`, проверяет истечение каждые 30 секунд и при `SIGINT`/`SIGTERM` ожидает текущую проверку с закрытием соединения; крайний срок завершения — 15 секунд. Для окружения с короткоживущими серверными функциями нужен этот отдельный постоянно работающий процесс: таймер функции не гарантирует фоновую работу. Однократная обработка:

```powershell
npm run holds:expire
```

Обе команды изменяют статусы просроченных броней в настроенной базе, сохраняя записи. Фоновый обработчик не удаляет историю и не создаёт платежи. Остановка PostgreSQL сохраняет данные; после восстановления подключения проверка продолжается.

Личная ссылка имеет вид `/appointment/<UUID>#token=…`. Фрагмент не передаётся в URL HTTP-запроса; интерфейс отправляет секрет только заголовком `Authorization: Bearer …`. В базе хранится SHA-256 токена, API не возвращает его. Неверный идентификатор или секрет дают одинаковый `404`; публичного номера недостаточно. Страница и API используют `no-store` и `Referrer-Policy: no-referrer`. Сервер сохраняет снимки салона, мастера, контактов, названий, цен, длительностей, перерывов и полные тексты согласованных условий. Позднее изменение или архивирование каталога не изменяет существующий визит.

Соединения PrismaPg и транзакции работают в UTC. Локальные даты и часы салона преобразуются отдельно по `SalonSettings.timezone`; часовой пояс устройства или значение по умолчанию PostgreSQL не сдвигают сохранённые моменты. Подробности — в [docs/DATABASE.md](docs/DATABASE.md).

## Настройки демонстрационного сценария

Начальные параметры находятся в `.env.example` и проверяются сервером в `src/lib/salon.ts`. Seed сохраняет их в `SalonSettings`; после загрузки каталога интерфейс, серверный расчёт и тексты условий используют проверенные значения из базы.

Окружение также задаёт предварительную оболочку до загрузки каталога или при недоступной базе. Каталог и цены при этом не подменяются. Изменение `.env` само по себе не изменяет строку `SalonSettings`; команда заполнения переносит настройки только в демонстрационную базу.

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `BOOKING_HORIZON_DAYS` | `60` | Горизонт календаря в днях |

## PostgreSQL

PostgreSQL нужен для каталога, серверного расписания, клиентов и записей. Сначала настройте `DATABASE_URL` в `.env`: команды миграций и заполнения выполняются именно для указанной базы. Не публикуйте строку подключения и пароль.

**Portable PostgreSQL для Windows.** Скрипт проекта загружает официальный архив EDB PostgreSQL **17.11-5**, проверяет опубликованный SHA-256 и распаковывает необходимые бинарники в `.local/postgres`. Данные хранятся в `.local/postgres-data`. Для первого запуска требуется доступ к сети.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-db.ps1
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

При первой инициализации скрипт выбирает свободный порт начиная с **5433**, слушает только `127.0.0.1`, создаёт отдельную роль приложения со случайным паролем и обновляет параметры подключения в `.env`. Файлы с паролями и каталог `.local` защищаются правами текущего Windows-пользователя и SYSTEM; `.env` и `.local` исключены из Git. Пользовательские настройки салона сохраняются. Если `.env` уже содержит другое подключение вместо демонстрационного примера, скрипт прекращает работу, сохраняя его. Не копируйте секреты в логи или документацию.

Повторный запуск использует существующий кластер и его сохранённый порт. Остановка сохраняет данные:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-local-db.ps1
```

После перезапуска компьютера запустите базу перед `npm run dev`. Диагностика запуска находится в `.local/postgres.log`; этот локальный файл не нужно публиковать.

**Docker.** Нужен установленный и запущенный Docker Desktop. Значения `.env.example` рассчитаны на этот вариант. В `.env` задайте согласованные `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT` и `DATABASE_URL`, затем выполните:

```powershell
docker compose up -d
npm run db:validate
npm run db:generate
npm run db:migrate
npm run db:seed
```

Дождитесь готовности PostgreSQL перед применением миграций. `db:migrate` применяет подготовленные SQL-миграции; `db:seed` записывает демонстрационный каталог. Этап 3 не предусматривает запасной каталог из файла при ошибке базы.

Остановить локальный контейнер с сохранением данных:

```powershell
docker compose stop
```

В текущей локальной базе применены четыре миграции: начальная схема, политика перерыва, снимки и отпечаток запроса записи, обновление только прежних демонстрационных текстов условий. SQL-ограничение пересечения дополнено серверными транзакциями, проверкой повторов и обработчиком истечения этапа 5. Подробности схемы и поведения seed — в [docs/DATABASE.md](docs/DATABASE.md).

## Ограничения текущей версии

Начальные услуги, мастера, графики и сведения о салоне демонстрационные. Каталог, расписание, клиенты, записи и тестовые платежи хранятся в PostgreSQL; временные брони закрывают интервалы, просмотр защищён личной ссылкой. Деньги не списываются. Внешний провайдер, официальный банковский sandbox и возвраты не подключены. Отправки email/SMS, настоящих отзывов и рейтингов нет. Защищённая админка, отмена, перенос и редактирование каталога пока не реализованы.

Сайт автоматически не публикуется. Создание, истечение записей и проверка тестовых платёжных событий реализованы. Административные операции и подготовка к размещению остаются для этапов 7–8.
